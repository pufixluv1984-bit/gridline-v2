# Gridline v2

Неофициальный некоммерческий фан-сайт о Формуле-1 для друзей и компаний. Две игры на одном сайте:

1. **Прогнозы** — угадываешь квалификацию, топ-10 гонки и бонусные ставки. Лиги на любое число игроков.
2. **Фэнтези-лига** — свой состав из 5 пилотов и 2 конструкторов на бюджет, свои правила (не копия официального F1 Fantasy).

Только десктоп (проверять на 1440 и 2K, мобильной версии нет). Автор: pufixluv. Язык интерфейса: русский.

Старый сайт на двоих (репозиторий `gridline`, VOVA против T-SHY) живёт отдельно до конца сезона 2026 и **не трогается**. Этот проект — новый репозиторий и новый проект Supabase.

## Прочитать перед началом работы

- `docs/PRODUCT.md` — механика: лиги, очки прогнозов, фэнтези, граничные случаи.
- `docs/ARCHITECTURE.md` — стек, модель данных, правила безопасности, потоки данных, порядок сборки.
- `docs/DESIGN.md` — токены дизайна, карта экранов, как читать макеты.
- `docs/FANTASY-FORMULA.md` — итоговая формула фэнтези (очки, цены, чипы, защита от злоупотреблений); главнее экрана правил в макете.
- `docs/FANTASY-REFERENCE.md` — справочник по официальной F1 Fantasy (очки, чипы, цены) и расхождения с макетом.
- `docs/SETUP-CHECKLIST.md` — что делает владелец руками (Supabase, OAuth, секреты).

## Стек (решено)

- Фронтенд: Vite + React 19 + TypeScript (strict), `HashRouter`, TanStack Query, `@supabase/supabase-js`, CSS Modules + CSS-переменные (без Tailwind: макеты рукописный CSS, так проще сохранить точность).
- Бэкенд: Supabase (Postgres, Auth, RLS, Edge Functions, `pg_cron`). Очки считает база, не браузер.
- Хостинг: GitHub Pages через GitHub Actions. Браузер никогда не ходит во внешние F1-API.
- Тесты: Vitest для фронта, pgTAP (`supabase test db`) для RLS и подсчёта очков.
- Пакетный менеджер: pnpm. Версии зависимостей фиксировать, не `latest`.

## Жёсткие правила

1. **Безопасность на стороне базы.** Любое правило (дедлайн, чужие прогнозы, роли лиги) обеспечивает RLS/триггер, а не интерфейс. Интерфейс только отражает его.
2. **Секретов во фронтенде нет.** Только публичный (`anon`/publishable) ключ в `VITE_*`. Ключ `service_role` никогда не попадает в браузер, репозиторий или сборку фронта.
3. **Очки считает SQL-функция**, идемпотентно (повторный запуск не дублирует). Фронт показывает готовые строки из `score_lines`.
4. **Время.** Всё в UTC, показ в поясе игрока. Таймеры и дедлайны считать от серверного времени (RPC `server_now()`), не от часов устройства.
5. **Никаких миграций «руками в консоли».** Схема только через файлы в `supabase/migrations/`, применять через Supabase CLI.
6. **Не тащить данные в браузер лишнего.** Чужие прогнозы до дедлайна не должны приходить в ответе вообще.
7. Работать по фазам из `docs/ARCHITECTURE.md`. Не начинать фазу, пока не принята предыдущая.
8. Перед каждой фазой коротко сверить с владельцем план, после — показать, что работает (скриншот или шаги проверки).
9. Не добавлять функции, которых нет в `docs/PRODUCT.md` или макетах, без вопроса.
10. Фото пилотов и машин, логотипы: права на них у владельцев. Набор владельца приходит отдельным архивом, распаковывать его в `public/assets/` как есть; трассы берутся только из дизайна (`docs/DESIGN.md`, раздел «Откуда брать ресурсы»), старые не использовать. Хранить в одной папке (`public/assets/`) и подключать через один модуль, чтобы можно было заменить на монограммы/рисунки без правок по коду. Футер с пометкой «неофициальный фан-проект» обязателен (текст в макетах).
11. **Скорость.** Бюджет: первая загрузка главной не больше ~250 КБ JS (gzip), у экранов с графиками и трассами подгрузка по требованию. Анимировать только `transform` и `opacity` (не `blur`/`box-shadow`/размеры); большие свечения статичные. Разбивать код по маршрутам (`React.lazy`). Шрифты Inter и Space Grotesk хранить у себя (латиница и кириллица, `font-display: swap`), не с Google Fonts. Фото в WebP нужного размера с ленивой загрузкой; каждая трасса отдельным SVG, подгружаемым при открытии. На сервере один запрос на экран (вью или RPC), без цепочек запросов. Кэш и мгновенный отклик (оптимистичные обновления) через TanStack Query. Регион Supabase: Европа (Франкфурт). Проверять Lighthouse (производительность не ниже 90 на десктопе) перед сдачей каждой фазы.
12. **Дизайн читается по одному экрану.** Источник: артефакт Claude Design со slug из `docs/DESIGN.md`. Перед каждым экраном прочитай его файл `.dc.html` (и версию `-2K`) инструментом `read_file` коннектора артефактов, затем делай. Если в `design/` лежит локальная копия, читай её. Если нет ни копии, ни доступа к артефакту, остановись и скажи владельцу, ничего не придумывай по памяти.

## Команды (после scaffold'а)

```bash
pnpm install
pnpm dev                 # Vite
pnpm typecheck && pnpm lint && pnpm test
pnpm build
supabase start           # локальная база (Docker)
supabase db reset        # применить миграции + seed
supabase test db         # pgTAP
supabase gen types typescript --local > src/lib/database.types.ts
```
